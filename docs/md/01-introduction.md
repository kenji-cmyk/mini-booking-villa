# 01 - VStay Villa Booking System

## Background / Context

VStay is a small villa booking platform created for a software requirements and system analysis assignment. The system focuses on the basic workflow of helping guests find villas, create bookings, make payments, and check booking or payment information. It also provides simple administration functions so an admin can manage villa information and booking status.

Villa booking is commonly handled through phone calls, messages, or manual records in small accommodation businesses. These methods can make it difficult for guests to check villa information clearly and for administrators to track booking requests consistently. VStay addresses this problem with a simple web-based system that keeps the booking process organized.

## Problem Statement

Guests need a convenient way to view available villas, check villa details, create bookings, cancel bookings when necessary, and view payment status. At the same time, administrators need a reliable way to manage villa records and monitor booking requests.

Without a centralized system, villa information may become inconsistent, booking records may be difficult to track, and payment status may not be clearly visible to users. VStay is designed to reduce these issues by providing a focused booking management system with only the essential features required for the assignment scope.

## Project Objectives

The main objectives of VStay are:

- To allow guests to view, search, and filter villa information.
- To allow guests to view villa details before making a booking decision.
- To allow guests to create, cancel, and view bookings.
- To allow guests to make payments and view payment status.
- To allow admins to create, update, delete, and view villa records.
- To allow admins to view all bookings and update booking status.
- To provide a clear system scope suitable for requirements analysis, use case modeling, and later design documentation.

## Target Users

| User Type | Description |
| --- | --- |
| Guest | A person who wants to browse villas, make a booking, cancel a booking, make payment, and view booking or payment information. |
| Admin | A system user responsible for managing villa records and updating booking status. |

## Project Scope

The scope of VStay is intentionally small and focused. The system includes the following areas:

- Guest villa browsing, searching, filtering, and detail viewing.
- Guest booking creation, cancellation, and booking detail viewing.
- Guest payment submission and payment status viewing.
- Admin villa management, including create, update, delete, and list functions.
- Admin booking management, including viewing all bookings and updating booking status.
- Basic validation for booking dates, required information, villa availability, and payment information.

The project is intended to support the main software engineering activities of a university assignment, including requirements specification, use case analysis, and system design.

## Out of Scope

The following features are not included in the VStay project scope:

- AI-based villa recommendation.
- Loyalty points, membership levels, or reward programs.
- Chat or real-time messaging between guests and admins.
- Multi-vendor marketplace features.
- Mobile application development.
- Complex revenue management or dynamic pricing algorithms.
- Advanced financial reporting or accounting modules.
- Villa owner self-service portals.
- Integration with multiple external payment gateways.
- Review, rating, or social media features.

## Expected Outcome

The expected outcome is a clear and realistic villa booking system specification that can be used in a final software engineering report. The documentation should describe what the system does, who uses it, what requirements it must satisfy, and what limitations are accepted within the assignment scope.

By the end of the project analysis phase, VStay should have a well-defined introduction, functional and non-functional requirements, use case list, business rules, assumptions, and constraints. These artifacts will support later design work such as diagrams, database design, user interface design, and implementation planning.
